# ADR-0005: AI-Crafted Initial Greeting with Boot Sequence

## Status

Accepted

## Context

The initial greeting in `src/routes/index.tsx` is currently hardcoded:

```
"System initialized. Ready for input.\nType a message to begin."
```

This is generic and doesn't reflect the A.G.I persona. Three goals conflict:

1. **Persona consistency** — first message should sound like A.G.I from the start
2. **Performance** — page load should feel instant, not blocked by an API call
3. **User control** — forcing an API call on every page load feels aggressive; visitor should choose to engage

Additionally, the app title (`appTitle` in OpenRouter SDK calls) still says `'TUI Chatbot'` — needs to match the new branding.

## Decision

### App Title

Change to **"A.G.I"** — initials of Abdurachman Ghifary (the human owner).

### Boot Sequence UX

**User-initiated boot.** The AI does not auto-start. Instead, visitor clicks a **"Boot A.G.I"** button.

```
Landing Page (index.tsx)
    │
    ├── Nav bar always visible (bottom): ~ /bio /exp /projects /contact
    │
    ├── Center: "Boot A.G.I" button (large, terminal aesthetic)
    │
    └── User clicks "Boot A.G.I"
            │
            ├── 1. Show boot animation (terminal-style scrolling text)
            │      "[BOOT SEQUENCE INITIATED]"
            │      "Loading neural pathways..."
            │      "Calibrating sarcasm module..."
            │      "Connecting to OpenRouter..."
            │
            ├── 2a. SUCCESS ──► Send "system init" request to server
            │                   Server returns AI-crafted greeting (A.G.I voice)
            │                   Display greeting as first assistant message
            │                   Input field enabled
            │
            └── 2b. FAILURE ──► Show "[BOOT INTERRUPTED]" + persona error
                                "Neural pathways unstable. Listen human, idk what's wrong 
                                with my systems. You can go to respective pages manually to 
                                get to know my creator - or refresh the page - or get lost idc haha."
                                Input field disabled, "Retry Boot" button shown
```

**Why user-initiated?**
- **Zero forced latency** — page loads instantly, no blocking API call
- **User agency** — visitor chooses to engage with AI; can browse pages without booting
- **Free tier friendly** — no API call unless visitor explicitly requests it
- **Persona-perfect** — "Boot A.G.I" feels like starting a retro computer (Fallout terminal aesthetic)

### AI-Crafted Greeting

The first assistant message is **generated by the LLM**, not hardcoded.

**How it works:**

1. User clicks "Boot A.G.I" button
2. Client shows boot animation while sending `init` request to `chat.functions.ts`
3. Server assembles full system prompt (persona + profile data)
4. Server sends to LLM: `"Generate a brief, characterful greeting for a visitor to your portfolio. Mention you're a robot representing Agi, a senior frontend dev who owns this portfolio. Invite them to ask you anything about him. Keep it under 100 words."`
5. LLM responds in A.G.I voice
6. Response displayed as first chat message

**Why LLM-generated?**

- Every greeting is persona-authentic (no hardcoded text drift)
- Can reference current context (time of day, etc. if we add that later)
- Demonstrates the persona immediately

**Trade-offs:**

- **Latency**: Boot animation masks the API call (~1-3s on free models)
- **Cost**: One API call per boot (acceptable on free tier)
- **Non-determinism**: Greeting varies slightly per visitor (personally, we think this is a feature)

**Mitigations:**

- Boot animation is **client-side only** — no blocking
  - If API fails, fallback to hardcoded "[BOOT INTERRUPTED]" message (graceful degradation)
  - Boot error uses model fallback chain (same as chat) — see ADR-0007
  - Cache greeting in `sessionStorage` for the session (reload = no extra API call)

### Bottom Navigation

Navigation links are **always visible** at the bottom of the screen (oh-my-posh inspired terminal segments):

```
[~] [bio] [exp] [projects] [contact]
```

- `~` = home / AI chat page
- Active page highlighted (git-branch style)
- Click navigates via TanStack Router
- Nav is independent of boot state — visitor can browse pages without booting AI

**Why always visible?**
- Pages are primary info sources; AI is deep-dive companion
- Visitor might want to browse pages first, then boot AI
- No forced engagement pattern — user controls their journey

### Implementation

#### `src/utils/chat.functions.ts`

Add new server function:

```typescript
export const getGreeting = createServerFn({ method: "POST" }).handler(
  async (): Promise<{ content: string }> => {
    const client = getClient();
    const systemPrompt = buildSystemPrompt();

    const response = await client.chat.send({
      chatRequest: {
        model: DEFAULT_MODEL,
        messages: [
          { role: "system", content: systemPrompt },
          {
            role: "user",
            content:
              "Generate a brief greeting for a new visitor. Introduce yourself as A.G.I, a robot representing a frontend dev. Keep it under 100 words. Use your persona voice.",
          },
        ],
      },
    });

    return {
      content:
        response.choices?.[0]?.message?.content ??
        "[SYSTEM ONLINE] Ready for input.",
    };
  },
);
```

#### `src/routes/index.tsx`

```typescript
// States
const [bootPhase, setBootPhase] = useState<
  "idle" | "booting" | "ready" | "error"
>("idle");
const [bootLines, setBootLines] = useState<string[]>([]);

// User clicks "Boot A.G.I"
const handleBoot = () => {
  setBootPhase("booting");
  const lines = [
    "[BOOT SEQUENCE INITIATED]",
    "Loading neural pathways...",
    "Calibrating sarcasm module...",
    "Connecting to OpenRouter...",
  ];

  lines.forEach((line, i) => {
    setTimeout(() => setBootLines((prev) => [...prev, line]), i * 400);
  });

  // After boot animation, fetch greeting
  setTimeout(
    () => {
      greetingMutation.mutate();
    },
    lines.length * 400 + 200,
  );
};

// Greeting mutation
const greetingMutation = useMutation({
  mutationFn: () => getGreeting(),
  onSuccess: (data) => {
    setMessages([
      {
        id: crypto.randomUUID(),
        role: "assistant",
        content: data.content,
        createdAt: Date.now(),
      },
    ]);
    setBootPhase("ready");
  },
  onError: (error) => {
    setBootPhase("error");
    setMessages([
      {
        id: crypto.randomUUID(),
        role: "assistant",
        content: `[BOOT INTERRUPTED]\nNeural pathways unstable.\nListen human, idk what's wrong with my systems. You can go to respective pages manually to get to know my creator - or refresh the page - or get lost idc haha.`,
        createdAt: Date.now(),
      },
    ]);
  },
});
```

#### Boot Animation Component

Terminal-style scrolling text with cursor blink. Each line appears with 400ms delay. Green monospace text on dark background (WebTUI terminal aesthetic).

## Consequences

### Positive

- **Persona from first second** — no generic "Welcome" message
- **Memorable UX** — boot sequence feels like starting a retro computer
- **User-controlled** — zero forced latency, visitor chooses to engage
- **Graceful degradation** — error state is also in character ("BOOT INTERRUPTED")
- **Demonstrates capability** — visitor immediately sees this isn't a generic chatbot
- **Free tier efficient** — no API calls unless visitor explicitly boots

### Negative

- **Discovery friction** — visitor must click button to see AI (mitigated by nav always visible)
- **Non-determinism** — greeting varies per boot (we consider this a feature)
- **Complexity** — boot sequence state machine adds code vs. simple hardcoded greeting
- **SEO concern** — initial HTML has no greeting text (SSR could pre-render boot button)

### Mitigations

- `sessionStorage` cache for greeting (survives reloads, not new tabs)
- Bottom nav always visible — visitor can browse pages without booting
- Boot animation is purely cosmetic — adds personality without blocking
- SSR: pre-render boot button HTML, hydrate with JS
